## 1. 这套母版怎样复用

复用的是业务归属、依赖边界、契约权威、质量门禁和交付纪律，不是对每个项目强制使用同一套框架。先选定客户端，再创建它的目录；不要初始化三个前端后保留两个空壳。

默认后端方案为 Python + FastAPI + SQLAlchemy/Alembic + PostgreSQL。TypeScript 依赖由 pnpm workspace 管理，Python 依赖由 uv workspace 管理。框架选择是本母版的工程建议，不是行业强制标准。两种 workspace 的实际能力见 [S01–S02](SOURCES.md#s01)。

适用：Web 业务系统、原生微信小程序及其 Python API、多客户端共享业务后端。其他客户端可以复用通用边界，但必须新增并验证专门的客户端实施说明；本包不宣称已覆盖 Flutter、桌面、嵌入式和所有云部署。

## 2. 三个客户端选项

| 选项 | 实施分册 | 默认适用目标 | 不应推导出的结论 |
|---|---|---|---|
| `web-vite` | [Vite](05-WEB-VITE.md) | 浏览器交互应用、管理后台、看板 | 不是说 Vite 永远不能 SSR |
| `web-next` | [Next.js](06-WEB-NEXTJS.md) | 需要框架路由、预渲染、服务端页面能力的 Web | 不是说 Python 后端必须被 Next.js 替代 |
| `wechat-native` | [微信小程序](07-WECHAT-MINIPROGRAM.md) | TypeScript + WXML + WXSS 原生小程序 | 不是说 React 页面能直接运行于小程序 |

Vite 是开发与构建工具；Next.js 提供更完整的 React 应用框架能力。Next.js 也可静态导出，但依赖动态服务端的能力受到限制。工具能力参考 [S05](SOURCES.md#s05)、[S07](SOURCES.md#s07)、[S09](SOURCES.md#s09)。这里的选择表是本母版的取舍建议。

同一个 `apps/web` 只选择一种生产框架。小程序和 Web 是不同真实客户端，确有需求时可以共同存在；这与同一业务逻辑保留两套重复实现不同。

## 3. 初始化必须填写的项目事实

将下表实例化为 `docs/architecture/project-profile.md`。该文件只记录当前项目事实，引用本包规范，不复制规范全文。

| 决策项 | 要填写的内容 | 放行条件 |
|---|---|---|
| 项目身份 | 仓库名、Python 包名、TS scope、产品目标 | 示例名已替换 |
| 客户端 | 已选择的客户端及对应应用目录 | 未选择的应用不创建 |
| Web 渲染 | SPA / Next 服务端 / Next 静态导出 | 镜像、路由、测试与选择一致 |
| 小程序构建 | 原生源码、仓库预编译到 dist、开发者工具版本 | 真正验证共享 SDK 打包 |
| 业务模块 | 名称、职责、公开接口、表归属、依赖方向 | 至少首个功能边界清楚 |
| 身份权威 | 身份提供方、浏览器登录、小程序身份接入 | 不信任客户端自报身份 |
| 授权权威 | 本地单一决策实现 / 独立授权服务 | 同一权限语义没有双权威 |
| 会话 | 各客户端凭据传递、有效期、撤销、刷新 | 安全设计和反向测试明确 |
| 数据库 | 引擎与实际版本、迁移管理、隔离方案 | 生产与集成测试契约一致 |
| 接口 | OpenAPI 版本、公开前缀、命名、兼容策略 | 生成器支持已实测 |
| 错误 | type URI 命名空间、错误命名、隐藏存在性策略 | 注册表与端点一致 |
| 依赖版本 | Node、Python、pnpm、uv、框架、生成器 | 工具生成有效锁文件 |
| 开发平台 | Linux/macOS/Windows 各自运行职责 | 小程序 GUI/CLI 路径已验证 |
| 部署 | 本地、测试、生产拓扑；TLS/代理归属 | 没有冲突的双代理规则 |
| SLO 与数据 | 可用性、延迟、容量、恢复、保留需求 | 有可测目标，不凭空写“生产级” |
| 可选能力 | Redis、对象存储、消息、worker、LLM 等 | 每项有实际需求与责任人 |
| 验收责任 | 谁审需求、代码、安全、发布；哪些 gate 阻断 | 无责任空白 |

未确定的信息写 `待确定` 并描述影响，不把示例当事实。影响身份、数据正确性或发布的未决项是门禁阻塞；不影响当前切片的未来需求可以暂不实现。

## 4. 推荐启用组合

**先做微信小程序：** `apps/miniprogram` + `apps/backend` + `packages/ts/api-client` + 通用规范。不开 `apps/web`。身份接入增加业务身份模块，授权仍只保留一个权威。

**先做内部 Web 工具：** `apps/web` 采用 Vite + `apps/backend`；先不创建 worker、Kafka、Redis、MinIO、Kubernetes。确有缓存、队列或存储需求再选工具。

**先做公开 Web 产品：** `apps/web` 采用 Next.js + `apps/backend`；逐类页面决定渲染和缓存。Python 仍拥有业务、权限与数据写入。

**小程序 + Web 管理后台：** 两个客户端使用同一错误契约、HTTP 契约和业务后端；前端 UI 分别实现。不要为了“共享”给小程序塞入 DOM/React 运行时。

## 5. 默认值不是永远不变的法律

改框架、改数据库、拆服务、换身份系统必须有明确变更理由、影响范围、迁移方案和证据；通过 ADR 批准后同步规范与实现。未经批准不能为了让工具运行方便而悄悄改技术栈。

当前包中的版本号 `2.0` 表示文档版本，不表示某个软件依赖版本。本文没有锁定“最新”软件版本；初始化和升级时应核对官方发布及安全状态，再生成真实锁文件。

## 6. 初始化完成的最低证据

一个新仓库的空目录不算初始化完成。至少需要：依赖按锁安装；选定客户端的真实运行；后端健康检查；一条真实 API 调用；契约生成与漂移检查；权限拒绝测试；数据库空库迁移；必要检查失败能阻止合并。

小程序账户、开发者工具或测试设备不可用时，可以完成文档和部分纯逻辑验证，但必须明确标记小程序运行验证未完成，不能用浏览器截图替代。
